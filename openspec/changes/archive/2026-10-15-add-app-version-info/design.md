# Design: add-app-version-info

## Context

Экран настроек (`SettingsScreen`) — Column сверху вниз: заголовок, подпись прозрачности, значение, слайдер, хинт; нижней привязки нет. `app/build.gradle.kts` уже генерирует `BuildConfig.VERSION_NAME` (из файла `version`), `VERSION_CODE` (2_000_100_000 + число коммитов) и `BUILD_DATE` (дд.ММ.гггг чч:мм), флаг `buildConfig = true` включён. В `app/src/main` `BuildConfig` пока не читается нигде — этот change делает первое чтение. Мотивация — в proposal.md.

## Goals / Non-Goals

**Goals:**
- Показать версию приложения и дату сборки в нижней части экрана настроек.
- Данные — только из `BuildConfig`, без новых градле-хуков и без чтения PackageManager.
- Соблюдение дизайн-системы: строки через `strings.xml`, отступы/типографика через токены.

**Non-Goals:**
- Тап-копирование версии, скрытые жесты, экран «О приложении».
- Показ `VERSION_CODE`/числа коммитов пользователю.
- Изменения сборки, сервиса, виджета, других экранов.

## Decisions

**D1. Источник значений — `BuildConfig`.**
Альтернатива — `PackageManager.getPackageInfo().versionName`: даёт versionName, но не даёт дату сборки и создаёт второй источник правды. `BuildConfig` покрывает оба значения, версия уже тянется из единого файла `version` релизным конвейером. Выбираем `BuildConfig`.

**D2. Размещение — bottom-блок через `Spacer(Modifier.weight(1f))`.**
В Column с `Arrangement.spacedBy` вставляем весомый пустой спейсер перед блоком версии — содержимое прижимается к низу, поведение элементов выше не меняется. Альтернатива `Arrangement.SpaceBetween` отвергнута: потребовала бы перестраивать цепочку spacedBy для всех детей и усложнила чтение кода.

**D3. Состав строки — «ChargeForecast 0.4.2 · сборка 14.10.2026».**
`VERSION_CODE` (2_000_1xx_xxx) и число коммитов в лоб не показываем — нечитаемо и не несёт пользы. Дату сборки оставляем осознанно: она «съезжает» между сборками одной версии, но отвечает на вопрос «что реально стоит» при баг-репортах.

**D4. Ресурс строки.**
Один шаблон `settings_version_info` = `%1$s %2$s · сборка %3$s` в `strings.xml` (секция «Настройки»): аргументы — `app_name`, `BuildConfig.VERSION_NAME`, `BuildConfig.BUILD_DATE`. Стиль — `MaterialTheme.typography.bodySmall` + `onSurfaceVariant`, верхний отступ `ChargeDimens.GapSmall`: новых токенов не требуется. Строку форматирует вызывающая сторона (`SettingsRoute` в `MainActivity`) либо сам экран получает готовую строку параметром — в текущей архитектуре экран не должен знать про `BuildConfig`, значения приходят параметром (по образцу `opacityPct`).

**D5. Прокрутка.**
Column оставляем не-scrollable: компактный набор элементов помещается даже на узких экранах. Если настройки начнут расти (пункт 8 дорожной карты) — ввести `verticalScroll` отдельным изменением.

## Risks / Trade-offs

- [На очень низких экранах с увеличенной системной шрифт-ссылкой контент может не влезть] → запас высоты большой (одна строка + спейсер съедает ровно свободное место); при появлении признаков — verticalScroll.
- [Дата сборки меняется между сборками одинаковой версии] → осознанный компромисс, ценность для баг-репортов выше (D3).
- [Активный change `fix-widget-and-discharge-remaining` правит другое требование `app-settings`] → дельты не пересекаются («назад» против версии), но при архивации первой из них вторая должна пройти `openspec validate`.
