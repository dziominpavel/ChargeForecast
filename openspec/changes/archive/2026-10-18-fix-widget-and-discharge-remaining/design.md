# Design: fix-widget-and-discharge-remaining

## Context

Мотивация и доказательства — в proposal.md. Технический контекст:

- Лог устройства (EMUI, Android 12+, targetSdk 36): `InflateException: Class not allowed to be inflated android.view.View` в `widget_battery`, строка 15 — это голый `<View android:id="@+id/widget_background">`, добавленный правкой b4bb646 слоем фона для непрозрачности. В safe-режиме RemoteViews лаунчер инфлейтит только классы из белого списка; `android.view.View` в него не входит (под префиксом `android.view.` допущен лишь `ViewStub`).
- `SessionEngine.dischargeEstimate()` (с 645393b) подаёт в `DischargeEstimator.estimate()` величину `capacity − counter` — «энергию до полного» — тогда как оценщик документирует аргумент как «остаток мкА·ч» и сам делит его на средний ток. Счётчик `BATTERY_PROPERTY_CHARGE_COUNTER` — заряд в батарее; тот же факт подтверждён комментарием в пути зарядки («счётчик — заряд В батарее») и тем, что `DischargeEstimator.update` считает `deltaUah = prev − counter` (счётчик убывает при разрядке).
- В `ChargeForecastApp` флаг `showSettings` ничем не обрабатывается на системное «назад»: без `BackHandler` стандартное поведение — закрытие Activity.

## Goals / Non-Goals

**Goals:**
- Виджет инфлейтится на устройствах с safe-режимом RemoteViews во всех трёх бакетах размера; непрозрачность продолжает работать.
- Оценка разряда монотонно убывает с разрядом и равна «остаток в батарее ÷ средний ток».
- Системная «назад» на экране настроек возвращает на экран сессии.
- Оба JVM-фикса закреплены тестами; фикс раскладок — проверкой на подключённом устройстве.

**Non-Goals:**
- Не трогаем `DischargeEstimator` (он правильный), `WidgetText`, `BatteryWidgetUpdater`, форматирование текстов.
- Не вводим Navigation Component — навигация остаётся ручной (решение проекта).
- Не меняем политику троттлинга виджета и приоры оценки.

## Decisions

**D1. Слой фона — `FrameLayout` вместо голого `View`.**
Альтернативы: (a) убрать слой фона и красить `widget_root` — но тогда непрозрачность гасила бы вместе с фоном и текст, ломая спеку app-settings; (b) `ImageView` с drawable — лишняя семантика, `FrameLayout` минимальный контейнер из белого списка. `id="@+id/widget_background"` и `background="@drawable/widget_background"` сохраняются — `setAlpha` в `applyBackgroundOpacity` работает с любым наследником `View`, метод-действие RemoteViews не меняется. Правятся все три лейаута: `widget_battery`, `widget_battery_narrow`, `widget_battery_wide`.

**D2. Остаток для разрядного оценщика — сам счётчик.**
`remainingUah = snapshot.chargeCounterUah` вместо `capacity − counter`. Альтернатива `capacity × levelPct` отвергнута: уровень квантован процентами, счётчик даёт непрерывную величину и уже является источником интервалов оценщика — числителе и накопитель говорят на одном языке. `capacityUah` в разрядном пути больше не нужен. Счётчик уже очищается в `BatterySnapshot` (`takeIf { it > 0 }`), отсутствие счётчика остаётся осознанной деградацией на приор (спека discharge-estimate).

**D3. `BackHandler` в `ChargeForecastApp`.**
`BackHandler(enabled = showSettings) { showSettings = false }` рядом с объявлением флага. Альтернатива `OnBackPressedDispatcher` в Activity — избыточна, Compose-решение в одной строке и в том же месте, где живёт навигация. Шестерёнка-тумблер не меняется.

**D4. Тест склейки — в `SessionEngineTest`.**
Юнит-тест строит снапшот с известными `chargeCounterUah`/`capacityUah` в разрядном режиме и проверяет, что переданный оценщику остаток равен счётчику (оценка «5% → десятки минут, не часы»). `DischargeEstimatorTest` не меняется — он уже проверяет оценщик с корректным входом. Раскладки виджета JVM-тесту не поддаются (Android-ресурсы) — проверяются на устройстве в задаче 5.2.

## Risks / Trade-offs

- [На старых лаунчерах без safe-режима `FrameLayout` — ничем не отличается] → фон и клики ведут себя идентично, риск нулевой.
- [После фикса оценки пользователь увидит резкую смену числа (14 ч → минуты)] → это честные цифры; ожидаемо, отдельной миграции не требуется.
- [Устройство без счётчика заряда: оценка уходит на приор] → уже осознанная деградация спека discharge-estimate, поведение не меняется.
- [EMUI может не перерисовать уже привязанный сломанный ячейку после обновления] → план проверки на устройстве включает перепривязку виджета после установки 0.5.0.

## Migration Plan

Релиз вышел как 0.5.0 (MINOR) вместе с `add-app-version-info` через штатный конвейер `release.ps1`; отдельный патч 0.4.3 не выпускался. Миграция данных нет; откат — предыдущий APK (подпись та же, обновление поверх встаёт).
