# Design: estimate-from-first-second

## Context

Мотивация — в proposal.md. Технический контекст:

- `DischargeEstimator` (чистый, JVM-тесты) копит кольцо интервалов разряда, `estimate(remainingUah, nowMs)` возвращает `collecting = true` при окне < 2 ч или мусорном среднем — UI и виджет показывают тексты-заглушки.
- `SessionEngine` при старте сессии читает медиану истории из `SessionCache` в `historyBaseRatePctPerMin` и передаёт в `HistoryBlender` — тот даёт число с первой секунды, если история есть, и живёт `null` (→ COLLECTING), если нет.
- `ForecastText.formatRemaining` (общий для экрана и виджета) всегда печатает секунды: «12 мин 30 с», «1 ч 23 мин 45 с».
- Виджет пушится с троттлингом 15 с (`BatteryWidgetUpdater`); режимы `WidgetMode.COLLECTING` и `NO_DATA` рисуют тексты-заглушки.
- `ChargeForecastService` публикует статичное уведомление с текстом «Слежение за зарядкой активно»; на устройстве автора строка видна вопреки `IMPORTANCE_NONE`.

## Goals / Non-Goals

**Goals:**
- Цифры остатка с первой секунды на обеих поверхностях (экран, виджет) без единого текста-заглушки.
- Плавный (без скачка) переезд разрядной оценки с приора «24 ч на полный» на измеренное среднее за окно.
- Убрать секунды из формата там, где они не несут информации (<1 мин остатка — единственное место с секундами).
- Служебное уведомление без текста.

**Non-Goals:**
- Точность разрядной оценки и калибровка констант приоров — считаются грубо, уточняются по наблюдениям на устройстве (не меняет спеку).
- Якорное сглаживание показа (закрытый change `smooth-anchored-countdown`) — вернуть отдельно, если минутные цифры на границах будут мигать.
- Долгосрочная память разряда за пределами 24-часового окна — приор и окно остаются единственными опорами.
- Персист и миграция состояния — ключи `SessionCache` не меняются.

## Decisions

### D1. Приор разряда живёт в `DischargeEstimator`, смесь — в домене времени

`estimate()` принимает уровень заряда (percent) дополнительно к `remainingUah` и возвращает число в любом случае:

```
priorSec(level) = (100 - level) / 100 * 24 ч

w = smoothstep(trackedMs : 0 .. 2 ч)     // 1 при пустом окне, 0 к 2 часам
measuredSec пригодна?  -> remainingUah / average * 1ч
                        : null  (w := 0 — держим приор)

remainingSec = w * measuredSec + (1 - w) * priorSec
```

- Приор считается от **уровня**, измеренное — от **счётчика**: обе опоры честны в своём домене, смешиваются в секундах.
- Среднее непригодно (ниже `MIN_CREDIBLE_DISCHARGE_UA`, нулевое, отрицательное) — `w = 0`, приор удерживается.
- `DischargeEstimate.collecting` удаляется; `averageCurrentUa = null` означает «не измерен» — UI прячет строку, а не показывает заглушку. `trackedMs` остаётся для журнала.
- `DischargeEstimate.NONE` (оценщик выключен, консервативный режим) сохраняет прежний смысл — заглушка «Не на зарядке» работает как прежде.

Альтернативы: жёсткое переключение на пороге 2 ч — отклонено (скачок числа, против обсуждения с автором); подмена дефолтного тока «измеренным» — отклонено (необъяснимо и нечестно).

### D2. Приор зарядки подмешивается в слот истории, `HistoryBlender` не меняется

```
historyBaseRatePctPerMin = cache.loadHistoryMedian(type) ?: ChargePrior.rate(type)

ChargePrior: AC 2ч, USB 6ч, wireless 4ч, unknown 3ч  (100% / N ч в %/мин)
```

- Приор — та же величина (%/мин), что медиана истории: все гейты смеси (smoothstep 10с→180с, floor 0.5 при «уточняю», приор живых замеров ниже порога) работают без изменений.
- `ChargeForecaster` не трогаем: ярус COLLECTING перестаёт достигаться при вставленном кабеле (скорость есть всегда), тексты-заглушки убираются на уровне UI.
- Значения приоров — константы с комментарием «калибруется»; они видны ≤1 минуты на устройстве, точность не критична.

Альтернатива: отдельная ветка приора внутри `ChargeForecaster` — отклонена (дублировала бы гейты смеси и ярусы точности).

### D3. Формат остатка — одна функция `ForecastText.formatRemaining`

```
< 60 с   -> "54 с"
< 1 ч    -> "45 мин"        (time_minutes)
>= 1 ч   -> "1 ч 23 мин"    (time_hours_minutes; при 0 мин — "1 ч")
```

Строки `time_minutes_seconds` и `time_hours_minutes_seconds` удаляются из `strings.xml` (им не остаётся случая). Экран и виджет меняются одновременно — оба используют эту функцию.

### D4. Виджет: без секунд, троттлинг зависит от остатка

- `WidgetMode.COLLECTING` удаляется из enum; `NO_DATA` рендерится пустым (без текста). Остаются `CHARGING`, `FULL`, `DISCHARGE`, `NOT_TRACKING`.
- `BatteryWidgetUpdater`: обычный интервал push — 15 с; когда режим CHARGING и `remainingSec < 60` — интервал 1 с (последняя минута, секунды на виджете убывают плавно). После возврата остатка выше минуты интервал возвращается к 15 с.
- В простое тика нет (design D10 прежнего change) — минутный формат скрывает редкие обновления.

### D5. Тексты: удаление строк и UI-веток

Удаляются из `strings.xml`: `session_collecting`, `session_measuring`, `session_discharge_collecting`, `session_discharge_collecting_hint`, `session_discharge_avg_pending`, `session_discharge_tracked`, `notification_tracking_active`, `widget_collecting`, `widget_measuring`, `widget_no_data`, `widget_short_collecting`, `widget_short_no_data`, `time_minutes_seconds`, `time_hours_minutes_seconds`.

- `SessionScreen`: ветка `remainingSec == null` на зарядке («Измеряю…») удаляется; `accuracyText` для `COLLECTING` прячет строку точности (недостижимо при вставке кабеля — приор даёт опору); карточка разряда показывает время + (если измерен) средний ток.
- `measuringOrCollecting` удаляется целиком.

### D6. Уведомление без текста

`buildNotification()`: без `.setContentText(...)` — остаются иконка и `contentTitle` (имя приложения). Канал, `IMPORTANCE_NONE`, статичность, `setOngoing` — без изменений.

### D7. Тесты

- `DischargeEstimatorTest`: приор при пустом окне; плавный переход (среднее на середине окна — смесь); удержание приора при мусорном среднем; полный уход от приора к 2 ч; уровень-фолбэк без счётчика.
- `SessionEngineTest`: первая зарядка без истории — прогноз с первой секунды по приору типа (нет COLLECTING); «Собираю данные» больше не возвращается.
- `WidgetTextTest`: COLLECTING исчезает; DISCHARGE с первым снапшотом; NO_DATA пустой.
- `SessionCacheTest`, `BatterySnapshotTest` — без изменений.

## Risks / Trade-offs

- [Приор «24 ч на полный» врёт для конкретного устройства] → уступает измеренному за ≤2 ч наблюдений; всегда помечен «≈».
- [Приор зарядки врёт для медленного USB на AC-зарядке] → живые замеры/история уводят за первые 3 минуты; значения — осознанная грубая константа.
- [Устройство без счётчика заряда: окно не заполняется, вечно приор 24 ч] → осознанная деградация (лучше стабильное грубое число, чем пусто); документируется в спеке.
- [Зарядка >24 ч подряд опустошает окно — возврат приора] → принято автором как фолбек.
- [EMUI показывает пустую строку уведомления вопреки IMPORTANCE_NONE] → пустая строка — максимум незаметности, доступный без отказа от foreground service.
- [Частые push'и виджета последней минуты (1 с)] → ≤60 с, кратковременно; троттлинг возвращается сам.

## Migration Plan

Без миграций: персист, ключи `SessionCache` и формат кэша не меняются. Откат — обычный revert приложения (старые строки вернутся, поведение вернётся к сборе-данных).

## Open Questions

- Значения приоров зарядки (2/6/4/3 ч) и горизонт гашения приора разряда (2 ч) — калибровать по наблюдениям на устройстве; константы, спеку не меняют.
- Округление минут вниз при формате «1 ч 0 мин» → «1 ч» — деталь реализации, решается в задаче формата.
