# Proposal

## Why

Виджет показывает «Слежение остановлено — откройте приложение» в двух случаях, и в одном из них он врёт. Признак живости — флаг сервиса в памяти процесса: как только сервис убит (оболочка EMUI, обновление, ручная остановка), флаг становится `STOPPED`, хотя процесс жив, данные обновляются и числа на экране верные. Обратная ложь тоже возможна: сервис подтвердил работу, а опрос батареи встал — виджет бодро показывает застывшее число.

Второе: на виджете нет действия. Единственный способ оживить слежение — открыть приложение, потому что `start()` вызывается только из Activity, из приёмника загрузки и из обновления пакета. Пользователь видит «остановлено», нажимает, приложение открывается и запускает сервис — отсюда ощущение «почему оно само не работает».

## What Changes

- Живость слежения перестаёт быть флагом сервиса и становится производной: свежесть последнего замера батареи плюс подтверждённый foreground-сервис. «Данные не обновляются» показывается только когда данные действительно стары, а не когда умер сервис.
- Виджет получает действие «Возобновить» вместо «откройте приложение»: тап по области состояния запускает слежение через `PendingIntent.getForegroundService` — из пользовательского действия платформа это разрешает.
- Причина остановки (запрет ОС, нет разрешения) сохраняется между запусками процесса, чтобы после смерти процесса виджет показывал причину, а не нейтральное «остановлено».
- Проводится проверка на устройстве: влияет ли невидимое служебное уведомление (`IMPORTANCE_NONE`) на то, что EMUI убивает сервис; по результату канал переводится на минимальную заметность или остаётся как есть.
- **BREAKING** для текстов: строка «Слежение остановлено — откройте приложение» заменяется на состояние с действием.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `background-tracking`: добавляются «Живость слежения определяется свежестью данных» и «Возобновление действием пользователя».
- `battery-widget`: меняется «Виджет честно деградирует» (состояние с действием вместо текста «откройте приложение») и добавляется «Действие возобновления на виджете».

## Impact

- `tracking/TrackingHealth.kt`, `TrackingHealthStore.kt`: свежесть, сохранение причины.
- `session/ChargeSessionMonitor.kt`: возраст последнего замера в состоянии.
- `widget/WidgetText.kt`, `BatteryWidgetProvider.kt`: новый режим состояния и PendingIntent возобновления.
- `service/ChargeForecastService.kt`: путь запуска из пользовательского действия, важность канала.
- `ui/TrackingStatusBar.kt`: согласованные тексты.
- `SessionRuntimeStore`: последний статус и причина (маленькая запись без частых перезаписей).
- Тесты: `TrackingHealthTest`, `WidgetTextTest`, `TrackingHealthStoreTest`.
