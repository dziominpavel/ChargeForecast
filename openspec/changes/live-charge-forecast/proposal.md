## Why

У автора несколько блоков зарядки и кабелей, непонятно какие быстрее. Нужно при втыкании кабеля в реальном времени видеть, сколько осталось до 100%, чтобы субъективно сравнивать оборудование. Сейчас приложение — заглушка без чтения батареи.

## What Changes

- Live-чтение состояния батареи во время зарядки (уровень %, статус, тип подключения, температура, ток/напряжение если доступны).
- Отслеживание скорости зарядки в реальном времени по дельте уровня заряда со сглаживанием (скользящее окно, больший вес последних минут).
- Экстраполяция прогноза времени до 100% с поправкой на медленную доводку после ~80% и честной вилкой точности (`±`, режимы «собираю данные» / «примерно» / «точно»).
- Постоянное уведомление в шторке через ForegroundService на время зарядки (уровень, скорость, остаток), автостарт при подключении и останов при отключении.
- Экран-заглушка заменяется на живой экран текущей сессии (те же данные, что в шторке). Ручной выбор кабеля/блока, история сессий, сравнение профилей, виджет — НЕ входят в scope.

## Capabilities

### New Capabilities
- `charge-forecast`: live-замер состояния батареи, расчёт скорости зарядки (%/мин) и прогноза до 100% с fallback на дельту уровня, когда ток/напряжение недоступны.
- `charge-notification`: показ прогноза в шторке через ForegroundService (старт/стоп по подключению, runtime-разрешения, обработка ошибок системы видимая пользователю).

### Modified Capabilities
- Нет (существующих спецификаций нет, `openspec/specs/` пуст).

## Impact

- Затрагивает: `MainActivity` + новый экран сессии, новый battery-слой (репозиторий/монитор), новый ForegroundService + канал уведомлений, `AndroidManifest.xml` (service, разрешения `POST_NOTIFICATIONS`, `FOREGROUND_SERVICE_*`), новая ViewModel на StateFlow.
- Зависимости уже есть (`lifecycle-service`, `lifecycle-viewmodel-compose`, `core-ktx`), новых библиотек не требуется. Зависимость `datastore-preferences` удаляется из `libs.versions.toml` и `app/build.gradle.kts` как лишняя (истории/профилей в scope нет).
- Риски: ток/напряжение доступны не на всех устройствах (обязателен fallback); точность первых 3–5 минут низкая (решается честным статусом); ограничения фона Android 10+ (только ForegroundService, без автозапуска Activity).
