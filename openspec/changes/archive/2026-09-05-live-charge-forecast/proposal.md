## Why

У автора несколько блоков зарядки и кабелей, непонятно какие быстрее. Нужно при втыкании кабеля в реальном времени видеть, сколько осталось до 100%, чтобы субъективно сравнивать оборудование. Сейчас приложение — заглушка без чтения батареи.

## What Changes

> **Решение автора (05.09.2026):** функционал шторки (уведомление + ForegroundService) удалён из продукта целиком — на устройстве он так и не заработал стабильно. Осталась только экранная поверхность. Спека `charge-notification` из дельты удалена.

- Live-чтение состояния батареи во время зарядки (уровень %, статус, тип подключения, температура, ток/напряжение если доступны).
- Отслеживание скорости зарядки в реальном времени по дельте уровня заряда со сглаживанием (скользящее окно, больший вес последних минут).
- Экстраполяция прогноза времени до 100% с поправкой на медленную доводку после ~80% и честной вилкой точности (`±`, режимы «собираю данные» / «примерно» / «точно»).
- ~~Постоянное уведомление в шторке через ForegroundService~~ — удалено (см. примечание выше).
- Экран-заглушка заменяется на живой экран текущей сессии. Ручной выбор кабеля/блока, история сессий, сравнение профилей, виджет — НЕ входят в scope.

## Capabilities

### New Capabilities
- `charge-forecast`: live-замер состояния батареи, расчёт скорости зарядки (%/мин) и прогноза до 100% с fallback на дельту уровня, когда ток/напряжение недоступны.

### Modified Capabilities
- Нет (существующих спецификаций нет, `openspec/specs/` пуст). Capability `charge-notification` отменена автором — её спека удалена из дельты.

## Impact

- Затрагивает: `MainActivity` + новый экран сессии, новый battery-слой (монитор на `ACTION_BATTERY_CHANGED` + `BatteryManager`), `AndroidManifest.xml`, новая ViewModel на StateFlow.
- Зависимости уже есть (`lifecycle-viewmodel-compose`, `core-ktx`), новых библиотек не требуется. Зависимость `datastore-preferences` удалена из `libs.versions.toml` и `app/build.gradle.kts` как лишняя (истории/профилей в scope нет); зависимость `lifecycle-service` удалена вместе с ForegroundService.
- Риски: ток/напряжение доступны не на всех устройствах (обязателен fallback на дельту уровня и sysfs); точность первых секунд низкая (честный статус «примерно» + живое обновление каждый тик).
