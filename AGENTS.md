# ChargeForecast — правила для AI-агента

Единый IDE-нейтральный источник always-on правил. Читается любым агентом (Cursor, Devin Desktop, Devin CLI и др.).

## Контекст проекта

Android-приложение на **Kotlin** для отслеживания процесса зарядки: прогноз времени до 100%, сравнение скорости разных зарядок и кабелей, история сессий.

### Идея (от автора)
У автора несколько зарядок и несколько разных кабелей к ним. Они заряжают телефон с **разной скоростью**. Приложение должно показывать, когда телефон ставится на зарядку:
- сколько времени осталось до 100%;
- текущую скорость зарядки;
- (в будущем) сравнение с прошлыми сессиями для этой же связки «зарядка + кабель».

Форма подачи — живой экран сессии (обновление каждую секунду; шторка-уведомление удалена из продукта решением автора 05.09.2026). В будущем: сравнение с прошлыми сессиями, виджет.

### Стек
- **Язык:** Kotlin
- **UI:** Jetpack Compose, Material 3
- **Данные:** SharedPreferences через `SessionCache` (ёмкость, сводка прошлой сессии, кривая доводки по типу подключения)
- **Архитектура:** один модуль `:app`, ручная навигация (без Navigation Component)
- **Тема:** палитра «Volt» — тёмный фон (Obsidian/Carbon) + единственный акцент Electric Volt (`#D1FF00`); токены в `ui/theme/` (`Color.kt`, `Type.kt`, `Theme.kt`)

### Ключевые пути
- Точка входа: `MainActivity` → `ChargeForecastApp()`
- Тема: `ui/theme/` (`Color`, `Type`, `Theme`)
- Версия: файл `version` (меняет только release-скрипт); автобампа при сборке нет

### Дорожная карта (наращивается в следующих сессиях)
1. Чтение состояния батареи через `BatteryManager` (уровень, статус, технология, температура, ток/напряжение) — сделано.
2. Секундный конвейер измерений и прогноз до 100% — сделано (тик 1 Гц, спидометры + fusion, кривая доводки, сводка прошлой сессии).
3. Калибровка констант spike-замером + контрольная живая сессия на устройстве автора — открыто.
4. ~~Постоянное уведомление в шторке~~ — удалено из продукта решением автора.
5. Виджет на домашнем экране (`AppWidgetProvider` + RemoteViews или Glance).
6. История сессий в UI; профили «зарядка + кабель» со средней скоростью (персист кривой уже есть).
7. Экраны: история, профили зарядок, настройки.

## Сборка и проверка
- Windows, оболочка PowerShell. Файлы в UTF-8, тексты на русском.
- Сборка: `.\gradlew.bat assembleDebug` (из корня проекта).
- Тесты: `.\gradlew.bat test` (unit), `.\gradlew.bat connectedAndroidTest` (instrumentation).
- Проверка в реальности — установка на устройство и наблюдение за зарядкой.

## Перед изменениями
1. **Сверяйся с `README.md`** — актуальное описание и статус.
2. **Версии и сборка:** зависимости из `gradle/libs.versions.toml`; версия приложения в файле `version` — автобампа при assemble/install/bundle нет.
3. **Тема:** новый UI — только через токены дизайн-системы (`MaterialTheme.colorScheme`, `MaterialTheme.typography`). Не вводить inline `Color(0xFF...)`, `.dp` и хардкод-формы в новых местах — выносить в `ui/theme/`.

## Приоритеты при доработках
- Не ломать точку входа и тему: экраны получают данные и колбэки из ViewModel (когда появится).
- Ошибки системы (батарея, уведомления, разрешения) обрабатывать и показывать пользователю (Snackbar/Toast), не глушить исключения.
- Разрешения запрашивать в рантайме корректно (если понадобятся новые).

## Структура ответов
- Код на Kotlin в стиле проекта: корутины, StateFlow, Compose.
- Комментарии и сообщения пользователю на русском, код и имена — на английском.
- При работе с батареей учитывать, что ток/напряжение доступны не на всех устройствах — иметь fallback на расчёт по дельте уровня заряда.

## Версии и changelog (обязательно)

- Версия проекта меняется **только в момент релиза**: бамп вне релиза запрещён,
  между релизами номер остаётся номером последнего релиза. У статического трека
  версия заморожена и не меняется вовсе.
- В changelog попадают **только глобальные доработки** — новая функция, заметное
  изменение поведения, фикс, который пользователь реально видит. Пункт пишется
  в секцию `## [Unreleased]` в момент работы, а не перед релизом. Мелочь
  (косметика UI: отступы, цвета, выравнивание, подпись элемента, и локальные
  правки без заметного эффекта), как и чистые доки, спеки, тесты, CI,
  внутренний рефактор, в changelog не пишется.
- Релиз (где есть конвейер): `release.ps1 -Prepare` → сборка артефактов в `dist/`
  → `release.ps1`. Порядок не меняется.
- Секция changelog начинается с **пользовательского саммари** — 2–5 строк о том,
  что изменится для пользователя, — **выше первой строки** `###`; под категориями
  (`### Добавлено`, `### Исправлено` и аналоги) идут инженерские детали: change-id,
  состав изменений, тесты, метрики. Подготовка релиза откажет, если саммари нет.
- Заметки GitHub-Release берутся из этого блока автоматически — отдельное
  описание релиза писать не нужно и нельзя дублировать.
- Сверка перед работой и после: `python scripts/check-version.py`
  (exit 0 — версия и changelog согласованы, exit 1 — рассинхрон).
- Полные правила и запреты: `docs/versioning.md`.
