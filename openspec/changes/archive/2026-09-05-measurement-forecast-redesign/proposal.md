## Why

Три симптома живой сессии автора: (1) строка «прошлая зарядка» всегда равна текущей скорости; (2) остаток времени прыгает «25 мин → 1 ч 25 мин»; (3) измерения не «живые» — не раз в секунду с нулевой секунды. Все три воспроизводятся чтением кода: шесть дефектов Д1-Д6 из `docs/improvements/02-measurement-forecast-redesign.md` (сверка с текущим кодом подтвердила актуальность каждого). Ключевые: текущая сессия непрерывно перезаписывает приор прошлой; прыжок складывается из трёх усилителей (пик тока в instant-оценке + 10-минутный бленд к честному замеру + мгновенное удвоение остатка на границе 80%); опрос 10 сек и тикер 30 сек ломают «живость», хотя ток и счётчик обновляются ~1 Гц.

## What Changes

- Фаза 0 — быстрые победы (конвейер прежний): `saveLastSpeed` только в конце сессии + замороженная сводка `SessionSummary` (avg CC-фазы без рампы и доводки); EMA тока (tau ~15 сек) вместо пика в instant-оценке; линейная интерполяция множителя доводки 1.0→0.5 между 80% и 90% вместо ступеньки ×2.
- Фаза 1 — секундный конвейер: `SystemClock.elapsedRealtime` для всех расчётов; опрос/тикер 1 сек на зарядке (10 сек на разряде); три независимых спидометра — S1 МНК по счётчику (окна 30 сек + 2 мин), S2 EMA тока, S3 дельта уровня (fallback); fusion по ярусам возраста сессии; остаток в мкА·ч (обход квантования уровня 1%); новый `DisplayFilter` (EMA tau=10 сек + округление до секунд каждый тик — без корзин); жизненный цикл с `plugDetectedAtMs` — секунда ноль от события кабеля, а не от первого `isCharging`.
- Фаза 2 — доводка без ступеньки: кривая множителей по 5%-корзинам 80-100% (дефолт 0.55/0.40/0.30/0.20, калибруется позже); интеграл остатка по корзинам; персист профилей по типу подключения (фундамент п.6 дорожной карты).
- Фаза 3 — юзабельность и калибровка: «Измеряю… N с» с живым счётчиком; spike-замер на устройстве автора → финальные константы (закрывает задачу 2.3 change `live-charge-forecast`); контрольная живая сессия 20+ мин (закрывает задачу 5.2). Адаптивный троттлинг шторки отменён вместе с самим функционалом шторки (решение автора).
- **BREAKING**: контракты `InstantSpeedEstimator` (пик → EMA), `ChargeForecaster` (ступенька → кривая корзин, ярусы) и `SessionCache` (замороженная сводка вместо непрерывной записи скорости) меняются; ни один unit-тест не удаляется без замены эквивалентным под новый контракт.

## Capabilities

### New Capabilities

- `charge-forecast`: live-замер батареи с секундным конвейером (три спидометра + fusion по ярусам), прогноз через фильтр показа (EMA + секунды каждый тик — без корзин), честные статусы точности, замороженная сводка прошлой сессии как приор, кривая доводки по корзинам.

### Modified Capabilities

- Нет: основные спеки (`openspec/specs/`) пусты — существующий change `live-charge-forecast` ещё не архивирован, его дельта определяет ту же capability. Дельта этого change'а перезаписывает требования из дельты `live-charge-forecast` («Расчёт скорости зарядки», «Прогноз времени до 100%», «Мгновенная оценка по току», «Кэш прошлой сессии», «Честная индикация точности»); при архивации первым архивировать `live-charge-forecast`, затем этот change.

## Impact

- Затрагивает: `session/ChargeSessionMonitor.kt` (тикер 1 сек, plugDetectedAtMs, конец сессии пишет сводку), `session/SessionCache.kt` (`SessionSummary`, профили-корзины), `forecast/InstantSpeedEstimator.kt` (EMA), `forecast/ChargeForecaster.kt` (ярусы точности, корзины, остаток в мкА·ч), `forecast/CounterSpeed.kt` (МНК по двум окнам), `battery/BatteryMonitor.kt` (POLL 1 сек на зарядке, elapsedRealtime, sysfs-фолбэк тока), `ui/SessionScreen.kt` (живой счётчик «Измеряю…»), `res/values/strings.xml`; новые `forecast/DisplayFilter.kt`, `forecast/SpeedFusion.kt`, `forecast/TaperCurve.kt`, `forecast/TaperCurveLearner.kt` (чистые, тестируемые). Новых зависимостей нет. Функционал шторки удалён из продукта (решение автора) — шторочных файлов в проекте нет.
- Риски: счётчик `CHARGE_COUNTER` и ток доступны не на всех устройствах — S3 (уровень) остаётся обязательным fallback; энергозатраты секундного опроса на зарядке несущественны (телефон у розетки), на разряде опрос возвращается к 10 сек.
- Порядок реализации: фаза 0 первой (30-60 мин, снимает симптомы 1 и 2), фазы 1-3 последовательно; каждая фаза самостоятельно поставляема и тестируема.
